# 出毛日记小程序：动态详情与互动流程代码审计

- **审计对象**：`pages/post-detail`，以及帖子详情、点赞、收藏、反应、评论、关注相关云函数。
- **审计方式**：静态源码审计；未部署云函数、未访问云数据库或微信运行时。
- **严重度口径**：P0＝流程中断、权限泄露或可产生错误数据；P1＝明显体验受损、状态不一致或功能不可完整使用；P2＝细节体验优化。

> **源码完整性说明**：任务指定的 `/home/ubuntu/chumao/utils/common.js` 和 `/home/ubuntu/chumao/app.js` 在当前共享源码树中均不存在。已尝试读取前者，并检索整个项目（排除 `node_modules`），均未找到。因此涉及 `app.callCloud` 的返回适配、`submitComment` 的异常归一化、`toggleOptimistic` / `rollbackOptimistic` 的实际实现，无法按要求读取验证；该缺失本身也是首个 P0 问题。

## 流程概述

1. 页面从 `options.id` 写入 `postId` 并调用 `loadPost`；成功后将帖子互动状态写入页面数据，并调用 `loadComments`（`pages/post-detail/post-detail.js:31-36,49-80`）。
2. 点赞、踩/种草、收藏均在客户端先乐观更新，再分别调用 `post-like`、`toggleReaction`、`post-favorite`（`pages/post-detail/post-detail.js:114-162`）。
3. 评论提交经公共 `submitComment` 封装后，本地 `commentCount + 1` 并重新拉取评论（`pages/post-detail/post-detail.js:251-263`）；云函数创建评论后更新帖子计数（`cloudfunctions/comment-create/index.js:108-141`）。
4. 分享按钮使用原生 `open-type="share"`，分享回调生成标题、路径和首图（`pages/post-detail/post-detail.wxml:103-106`；`pages/post-detail/post-detail.js:189-206`）。作者头像区可跳转作者主页（`pages/post-detail/post-detail.wxml:24-33`；`pages/post-detail/post-detail.js:178-187`）。

## 已验证正确的部分

1. **点赞 action 字面协议一致**：客户端实际只发送 `like` 或 `unlike`（`pages/post-detail/post-detail.js:114-118`），云函数也只接受这两个值（`cloudfunctions/post-like/index.js:23-27`）。在 `toggleOptimistic` 确实先翻转 `isLiked` 的前提下，`isLiked ? 'like' : 'unlike'` 的时序是正确的；但该 helper 文件缺失，无法验证其内部实现，见“未验证的假设”。
2. **反应返回结构不会覆盖页面其他状态**：`toggleReaction` 的 `setData(res.data)` 只是局部合并页面数据（`pages/post-detail/post-detail.js:141-146`）；云函数返回严格的四个扁平字段 `reactionUp`、`reactionDown`、`reactionUpCount`、`reactionDownCount`（`cloudfunctions/toggleReaction/index.js:80-88`），与页面使用字段相同（`pages/post-detail/post-detail.js:15-24`）。不存在 `res.data` 直接覆盖整个 `data` 或覆盖 `post/comments` 的证据。
3. **收藏 action 协议一致**：客户端按翻转后的状态发送 `favorite` / `unfavorite`（`pages/post-detail/post-detail.js:155-159`），云函数校验并实现相同枚举（`cloudfunctions/post-favorite/index.js:22-25,46-79`）。问题在于确认前 Toast 和失败反馈，而非 action 值不匹配。
4. **回复会落到提交时选中的父评论，且云端校验归属**：页面传递 `replyTo._id`（`pages/post-detail/post-detail.js:213-216,251-257`）；云函数校验该评论存在并且 `targetId`/`targetType` 同属当前内容，再写入 `parentId`（`cloudfunctions/comment-create/index.js:81-106`）。列表函数按 `parentId` 把回复挂回顶级评论（`cloudfunctions/comment-list/index.js:34-52`）。
5. **单次评论成功后的基本刷新路径正确**：页面仅在 `doSubmitComment` 返回成功后清空输入、`commentCount + 1` 并调用 `loadComments`（`pages/post-detail/post-detail.js:251-263`）；云函数在成功返回前写评论并更新 `commentCount`（`cloudfunctions/comment-create/index.js:108-141`）。该结论不覆盖问题 4 的部分失败和问题 5 的连点场景。
6. **分享文案和素材有合理回退**：分享标题取正文前 50 字，正文为空时使用默认文案；分享路径/朋友圈 query 都携带帖子 ID；首图不存在时传空字符串（`pages/post-detail/post-detail.js:189-206`）。
7. **关注状态具有数据库持久化与回读机制**：`followUser` 在 `follows` 写入/删除关系（`cloudfunctions/followUser/index.js:50-68,98-105`），`getUserPublicContent` 用该集合计算 `isFollowing`（`cloudfunctions/getUserPublicContent/index.js:46-54,79-80`）。因此“关注后状态不持久化”未被源码证实。

## 未验证的假设与运行时问题
