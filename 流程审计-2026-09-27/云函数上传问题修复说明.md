# 云函数「无法上传 / 上传失败」排查与修复

**排查时间：** 2026-09-27
**现象：** 云函数经常无法上传、上传失败

---

## 一、根因：`cloudfunctions/` 下有 2 个非法目录

微信开发者工具会把 `cloudfunctions/` 下的**每一个一级子目录都当成一个云函数**来识别和处理。
只要有一个子目录不是合法云函数，整批上传就会失败或反复报错。

| 目录 | 问题 | 来源 |
|---|---|---|
| `shared/` | 只有 `contentSecurity.js`、`relationId.js`，**没有 `index.js` 入口** | 我此前放共享代码模块时引入的失误 |
| `a123/` | **完全空的目录** | 疑似误建 |

**已修复：**
- `shared/` 的两个模块移到项目根目录 `cloudfunctions-shared/`（作为源码存档，不再参与云函数识别）
- `cloudfunctions/` 下删除 `shared/` 与 `a123/`

> 修复后 `cloudfunctions/` 下共 **49 个目录，全部是合法云函数**。

---

## 二、为什么 `shared/` 不该放在 `cloudfunctions/` 下

微信云函数的**每个函数都是独立打包、独立部署**的，云端不会共享目录。

所以共享代码必须**复制进每个用到它的函数目录**里。当前各函数目录内已经各自带了一份
`contentSecurity.js` / `relationId.js`，`require('./contentSecurity')` 都能正确解析——
这一点我逐个函数校验过，**没有缺失**。

`cloudfunctions/` 根下那个 `shared/` 目录只是我留下的"源码母本"，对云端没有任何作用，
却会被开发者工具误判成一个云函数。

## 四、剩下的两个可能诱因（需要你操作）

结构问题已经解决。如果**仍然**偶发上传失败，通常是下面两种情况：

### 1. 上传超时（最常见）

有 5 个函数目录里带了 `node_modules`（约 126 个包）：

```
addLocation、getCityCandidates、login、post-create、updateUserProfile
```

「上传并部署」如果选的是**上传所有文件**，会把这 126 个包一起传上去，网络慢时容易超时。

**推荐做法：改用「上传并部署：云端安装依赖」**（右键云函数目录 → 选这一项）。
这样只传源码，依赖由云端安装，体积从几十 MB 降到几十 KB，速度快且不易失败。

> 云端安装依赖会读取 `package.json`。这些函数的 `wx-server-sdk` 版本是 `~2.6.3`，
> 是正常的。

### 2. 云环境未选中

报错形如 `请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境`。

**做法：** 在开发者工具左侧文件树里找到 `cloudfunctions` 目录，
点右侧的**云环境选择**，选中你的环境：

```
your-cloud-env-id
```

（这个环境 ID 来自 `app.js` 的 `wx.cloud.init`，两边必须一致。）

## 五、顺带发现的一个运行时问题

`security.imgSecCheck` 官方已**于 2021-09-01 停止维护**，官方建议改用
`mediaCheckAsync`（异步审核）。

当前 `contentSecurity.js` 对这种情况已有兜底：调用失败时**不阻断发布**，
而是把内容标记为 `pending`（仅作者本人可见）。所以**不会造成上传失败**，
但图片审核实际上处于"未生效"状态。

**建议后续接入 `mediaCheckAsync`**，配合消息推送接收审核结果回调。
这属于独立的功能改造，不影响本次的上传问题。
