# 地点海报「不显示」+ 小程序码失败 · 诊断与修复（第三轮）

**诊断时间：** 2026-09-27
**现象：** ① 地点海报没有生成（画布区域空/一条细边）② 扫码入口没有 ③ 小程序码生成失败 ④ 点「重新生成」没有任何错误码

**结论：这是两个互不相关的独立问题，而且我上一轮的处理方式本身有问题。**

---

## 问题一：海报「没有生成」——是 CSS 把画布压扁了（前端问题）

### 根因

`share-card.wxss` 里这条规则：

```css
.share-canvas { width: 100% !important; height: auto !important; }
```

而画布的尺寸是**行内样式**给的：

```html
<canvas style="width: 630px; height: 1000px;"></canvas>
```

`!important` 的优先级高于行内样式，于是：
- `width: 100%` 生效（撑满容器）
- `height: auto` 生效 → 对 `<canvas>` 而言，`height: auto` 会回退到**属性默认高度 150px**（不是按宽高比推算）

结果：一个 630×1000 的海报被显示成一条**又宽又扁的横条**。加上 `overflow: hidden` 的容器裁切，看起来就像"海报完全没有生成"。

这解释了你的描述——**海报其实一直在正常绘制，只是被 CSS 压扁到几乎看不见**。

### 修复

- 移除 `!important` 覆盖，改为 `width: 100%; height: 1051rpx;`
  （662rpx 宽 × 1051rpx 高，与 630×1000 的逻辑画布严格同比，不变形）
- 画布标签简化为 `<canvas type="2d" id="shareCanvas" class="share-canvas"></canvas>`，尺寸统一由 CSS 决定，避免两处尺寸互相打架

## 问题二：小程序码失败——**极可能是小程序尚未发布**（平台限制，非代码问题）

### 关键限制

官方文档对 `wxacode.getUnlimited` 的 `check_path` 说明：

> **check_path** 默认是 true，检查 page 是否存在，为 true 时 **page 必须是已经发布的小程序存在的页面**（否则报错）；为 false 时允许小程序未发布或者 page 不存在。

对应错误码 **41030**：

> page 路径不正确：根路径前不要填加 /，不能携带参数，**需要保证在现网版本小程序中存在**，与 app.json 保持一致。

**重点：`check_path` 只豁免"页面路径检查"，不豁免"小程序必须已发布"这个前提。**

社区开发者原话：

> 不发布又生成不了小程序码，发布的话相当于发布的版本中生成小程序码的功能不能使用，简直是个流氓！

也就是说：**只要小程序从未发布过线上版本，`getUnlimited` 就会一直失败。** 这与你"点击重新生成没有任何错误码返回"的现象完全吻合——云调用直接抛错，而错误信息被吞掉了。

### 另一个可能原因：云函数尚未重新部署

我上一轮创建的 `config.json`（声明 `wxacode.getUnlimited` 云调用权限）**只有在你重新部署 `generateShareCode` 后才生效**。若未部署，调用会返回 **-604101（权限未声明）**。

## 为什么你看不到错误码——我上一轮的处理有问题

上一轮我写的是：

```js
catch (err) {
  this.setData({ qrCodePath: '', qrError: '小程序码暂不可用' })   // ← 硬编码文案，把原因吞了
}
```

我把真实错误信息丢掉了，只留一句无法定位问题的固定文案。**这是我的疏忽**——加了失败提示，却没有让提示携带可操作的信息，等于只告诉你"坏了"却不告诉你"哪里坏了"。

### 修复：把真实原因透出到界面

现在会显示：

- 云函数返回错误码时 → `小程序码生成失败（错误码 -604101）`
- `callCloud` 抛异常时 → `小程序码暂不可用：<真实错误信息>`

云函数侧也补齐了三处诊断信息透出：
- 调用返回体里带 `errcode` 但无图片数据时，返回该错误码
- `catch` 到异常时透出 `errCode`，并针对 `-604101` / `-41030` / `40001` 给出**中文可操作提示**
- `config.json` 补齐 `name` / `type` 字段，与项目内既有云函数（`getEvents` 等）格式完全一致，避免 DevTools 解析歧义

## ⚠️ 你需要做的两件事

### 1. 重新部署云函数（必须）

在微信开发者工具中，对 **`generateShareCode`** 右键 →「上传并部署：云端安装依赖」。
（其余 6 个审核相关云函数同理，但**小程序码只依赖 `generateShareCode`**。）

> 只改本地 `config.json` 不重新部署是**不会生效**的——云端仍运行旧版本，权限依旧未声明。

### 2. 确认小程序是否已发布（决定性问题）

这是我最怀疑的原因。请告诉我：

- **这个小程序（appid `wx0000000000000000`）是否已经发布过正式版？**

- 若**从未发布** → `getUnlimited` 在平台层面就不允许调用，无论代码怎么改都会失败。可选方案：
  1. 先发布一个版本（推荐，一劳永逸）
  2. 或改用 `wxacode.get`（接口 A）——它同样要求已发布，**无法绕过**
  3. 或暂时用「小程序码 + 文字提示」降级方案，发布后再启用二维码

- 若**已发布** → 部署 `generateShareCode` 后重试，并把界面显示的错误码告诉我，我按码继续排查：

| 错误码 | 含义 | 处理 |
|---|---|---|
| `-604101` | 云调用权限未声明 | config.json 未生效，确认已重新部署 |
| `-41030` | 页面在现网版本中不存在 | 需发布包含该页面的版本 |
| `40129` | scene 不合法 | 传入了非法字符 |
| `40001` | 凭证异常 | 检查 AppSecret |

## 顺带说明：海报即使没有小程序码也应该能看

代码里本就有兜底逻辑——取不到小程序码时，底部会画一个带「出」字的占位块 + 「在微信内打开地点详情」文案，**海报其余部分（封面、标题、地址、拍摄建议、评分）应正常显示**。

如果你看到的是"整张海报都没有"，那就印证了**问题一是画布被 CSS 压扁**（与小程序码无关）。修复后海报应立即恢复正常显示，二维码则取决于上面第 2 点的答案。
