# 出毛日记小程序 · 核心使用流程检查结论（摘要）

**检查时间：** 2026-09-27
**检查对象：** 收藏地址、发表动态、分享地址名片（海报/小程序码）等正常使用流程
**检查方式：** 7 条流程并行静态审计 + 父级逐条复核关键结论 + 微信开发者工具编译与页面预览验证
**检查工具状态：** 开发者工具已连接并登录；发表页、动态详情页、发现页、我的页均已成功编译并生成预览二维码

---

## 一、一句话结论

**核心流程整体可用，但有三处“用户一定会踩到”的硬伤：扫码分享回不来、收藏数会长期算错、连点会重复写入。** 这三类问题不需要新功能，属于必须修的“地基”，建议优先于任何新特性开发。

---

## 二、必须立刻修的 7 个 P0

| # | 流程 | 问题 | 用户实际会看到什么 |
|---|---|---|---|
| 1 | **分享地址名片** | 小程序码写入 `scene=id=xxx`，但地点详情、活动详情、路线页只读 `options.id`，**完全没解析 `scene`** | 用户保存海报分享给朋友，朋友扫码**打不开对应内容**（路线页还会直接返回上一页）——分享链路在最关键一步断掉 |
| 2 | **分享地址名片** | 海报的小程序码 ID 校验上限为 28 字符，而云开发文档 `_id` 是 32 位 | 若 ID 超过 28 位，码**永远生成不出来**，海报上只有“正在准备中”的占位方块 |
| 3 | **分享地址名片** | 动态详情页有“生成分享卡片”入口，但海报页只支持地点/活动/合集 | 点进去**必然报错**“暂不支持生成此类海报” |
| 4 | **收藏地址** | 收藏关系用“先查再增删”，没有事务或唯一键；取消时只删第一条 | 快速连点或弱网重试会**插入重复收藏**，取消一次后仍是“已收藏” |
| 5 | **收藏地址** | 收藏数没有单一数据源：详情页精确统计、发现页只聚合前 100 条、排行榜读一个**从来没人维护的字段** | 同一个地点在详情、发现卡片、排行榜上显示**三个不同的收藏数**；热度排序失真 |
| 6 | **发表动态 / 动态互动** | 点赞、收藏、反应、评论都**没有提交锁**，也没有原子性 | 连点会发出重复请求，可能出现重复评论、计数错乱，或“提示失败但其实成功了” |
| 7 | **发表动态** | 审核服务异常时直接放行（fail-open），但写入的内容仍会被公开列表返回 | 审核服务故障期间，未过审内容对所有人可见 |

## 三、值得一并修的 P1（按用户感受排序）

**收藏地址**
- 在详情页收藏后返回发现页，卡片、地图标点、热度**都还是旧状态**（没有跨页同步机制）。
- 地点详情页点收藏**没有登录校验**，而发现页卡片有——同一件事两个入口两种表现。
- “加入合集”在断网时**静默失败**，用户以为加进去了。
- 重复加入同一合集仍提示“已加入合集”。

**发表动态**
- 发布成功后 1.5 秒内按钮会重新解锁，**可以连点发两条**。
- 草稿把本地临时图片路径存进 Storage，重启小程序后路径失效，但**仍会提示“恢复草稿”**，恢复后发布只报一个笼统的网络错误。
- 前端允许 10 个装备标签，新建云函数只允许 8 个，编辑接口**完全不校验**——用户可能在最后一步才发现被拒。
- 图片先上传、被后端拒绝后**不回收云存储文件**，产生孤儿文件。
- 发布后返回动态列表**看不到刚发的内容**，需要手动下拉。
- 超过 1 MiB 的图片被提示成“图片包含违规内容”，文案严重误导。

**分享地址名片**
- 海报的“最佳拍摄/推荐季节/地点评分”三个信息位被活动、合集**强行复用**：活动报名人数被显示成“推荐季节”，评分还会拼上“/ 5”。
- 小程序码生成失败只写 console，用户**能保存一张扫不出结果的废海报**。
- 相册权限被拒后只打开设置页，**授权成功也不会自动续存**；保存按钮可重复点击。
- `shareCount` 有读无写，**永远是 0**，但被算进了热门排序。

**动态详情互动**
- 收藏是“先弹成功提示，再发请求”，失败只静默回滚——**用户会被误导为已收藏**。
- 评论加载失败被显示成“没有评论”，且只显示 20 条、**没有加载更多**。
- 作者栏“⋯”按钮用的是 `bindtap`，点击会**同时跳进作者主页**。
- 云函数返回错误码时，页面会把整个错误对象**当成帖子渲染**，出现空白详情。
- `comment-list` 不校验内容可见性，知道 ID 就能**读到圈内/已下架内容的评论**。

**发现页**
- 搜索时“联想请求”和“正式搜索”共用版本号：快速点搜索会**让正式请求被丢弃，骨架屏永久转圈**。
- “附近”其实**没按附近查**——传了经纬度但云函数不使用，按全库最新返回，跨城出现错误地点。
- 定位失败时保留上海默认坐标，用户**无法区分“没授权”“网络失败”“真的没地点”**。
- 地图列表**没有触底分页**，实际只能浏览首批地点。
- 已收录的地图 POI 若不在当前列表，会**丢掉内部地点 ID**，导致进详情或收藏失败。

**登录与我的页**
- 我的页收藏 Tab **只显示地点**，但统计数字包含动态收藏——收藏了动态数字会涨，列表里却找不到。
- 保存个人资料后**不会同步建立应用登录态**，用户以为登录了其实没有。
- 用户主页资料字段漂移：编辑用 `furName/signature`，公开接口输出 `bio/fursuitName`——**自己资料正常，别人看你主页是空的**。
- 用户主页请求失败后 `loading` 不关闭，**永久骨架屏**。
- 账号封禁的提示在各页面**不一致**，有的静默回滚。

## 四、已验证正确的部分（不用改）

- 收藏关系字段（`targetId/targetType/userOpenId`）在各云函数间命名一致，不存在“字段错配导致收藏查不到”。
- 内容/图片至少一项、500 字上限、9 张图上限、普通标签 5 个且每个 10 字，前后端都有覆盖。
- 帖子点赞的 `like/unlike` 枚举、反应返回字段、回复挂载逻辑与页面调用一致。
- 小程序码白底、封面渐变兜底、`cloud://` 转临时链接、630×1000 画布与 1260×2000 导出比例都正确。
- 我的页有收藏空态、骨架屏和错误重试组件；设置页跳转收藏 Tab 能正确生效。
- 发现页地图标点已放大到 38×46、用 `cover-view` 规避原生层遮挡、有重复事件抑制。
- 单条消息已读会校验归属，评论回复会校验父评论同属一个目标内容。

## 五、建议的修复顺序

**第一批（本周内，P0）**
1. 三个扫码目标页统一解析 `scene` 中的 `id`，并放宽小程序码 ID 长度校验。
2. 收藏/点赞/反应/评论改为确定性关系 ID + 事务，评论加 `requestId` 幂等；历史数据去重并重算计数。
3. 收藏数收敛到单一真源（推荐在事务里维护 `locations.favoriteCount`），详情/发现/排行榜统一读取。
4. 互动按钮加提交锁；收藏的成功提示移到服务端确认之后。
5. 审核策略统一（优先 fail-closed，或让 `review` 内容仅作者可见）。

**第二批（本轮迭代，P1）**
- 收藏跨页同步（事件广播 + `onShow` 兜底）、加入合集的错误捕获。
- 发布成功后锁到跳转完成；草稿改用 `wx.saveFile` 稳定路径；前后端共享一套校验。
- 海报按类型用结构化字段绘制；帖子海报要么实现要么移除入口；二维码失败给出可重试的错误态。
- 详情页评论分页与错误态；作者栏“⋯”改 `catchtap`。
- 发现页按坐标查询 + 显式定位失败态 + 触底分页 + 保留 `matchedLocationId`。
- 我的页收藏语义统一（全部/分类型）、资料 schema 统一、用户主页 loading 兜底。

**第三批（后续优化，P2）**
- 上传进度与单图重试、真实尺寸错误文案；海报保存防重与授权续办；长标题省略号；详情页直达关注。

## 六、需要在真机或云端才能最终确认的

1. 云函数是否已部署为当前版本（历史上出现过本地与云端不一致）。
2. 云数据库集合与索引是否齐全（`favorites`、`likes`、`reactions`、`checkins`、`messages`、`collections` 等）。
3. 取一条真实文档 `_id` 确认长度是否超过 28（决定第 2 个 P0 是否成立）。
4. `msgSecCheck/imgSecCheck` 的配额、超时与是否有复审任务。
5. 真机验证：小程序码扫码回流、相册授权回调、Canvas 导出质量、定位拒绝、`tempFilePath` 回收时点。
