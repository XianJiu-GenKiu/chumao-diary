## P0-04｜分享地址名片扫码回流断裂

**根因（两层，都会独立导致失败）**

1. `generateShareCode` 写入 `scene=id=xxx`，但地点详情、活动详情、路线页只读 `options.id`，**从未解析 `scene`**。扫码进入时 `options.id` 为空 → 页面无数据。路线页更是直接 `navigateBack()`。
2. `scene` 硬校验 `/^id=[A-Za-z0-9_-]{1,28}$/`，而微信 `wxacode.getUnlimited` 的 **scene 上限是 32 个可见字符**；`id=` 前缀已占 3 字符，留给 ID 的只有 28 位，而云开发文档 `_id` 本身就是 32 位 → **必然超限，码永远生成失败**。

**修复**

- 新增 `utils/scene.js`：`parseSceneId(options)` 统一解析，同时兼容 `id` 参数、裸 ID scene、旧版 `id=xxx` scene、URL 编码形式与带附加参数的 scene；`buildScene(id)` 生成符合 32 字符限制的 scene。
- 三个扫码目标页（`location-detail` / `event-detail` / `route-plan`）改用 `parseSceneId`，并在无有效 ID 时给出「链接已失效」提示而非停在骨架屏。
- `generateShareCode` 改为接受裸 ID（不再加前缀），校验放宽到 32 字符，同时保留对旧 `id=xxx` 入参的兼容。
- `share-card` 改传裸 ID；新增 `qrError` 状态，码生成失败时明确提示「扫码入口暂不可用」并提供重试，**不再让用户保存一张扫不出结果的废海报**。

**验证：** scene 解析 9 个用例全部通过（直接 id / 裸 scene / 旧格式 / URL 编码 / 带附加参数 / 32 位 ID / 空值 / 非法值）。

## P0-03｜写操作缺少原子性与幂等性

**根因**

关系写入全部是「先 `where` 查询再 `add`/`remove`」，且关系写入与计数更新是两次独立请求：

- 并发或重试时同一用户对同一目标会插入**多条关系记录**；
- 取消收藏只删除第一条，残留记录让「已收藏」状态无法真正取消；
- 计数与关系可能只成功一半，长期漂移；
- 收藏数有三个来源（详情精确统计 / 发现页只聚合前 100 条 / 排行榜读一个从不维护的字段），同一地点显示三个不同数字。

**修复**

- 新增 `cloudfunctions/shared/relationId.js`：`relationId(scope, ...parts)` 用 MD5 生成**确定性关系 ID**。同一用户对同一目标永远命中同一条记录，重复请求在数据库层面天然幂等，不再依赖先查询。
- 五个云函数改为「确定性 ID + `runTransaction`」，**关系写入与计数增减在同一事务内完成**：
  - `toggleFavorite`（地点收藏）
  - `post-favorite`（动态收藏）
  - `post-like`（动态点赞）
  - `toggleReaction`（种草/踩雷，含 up↔down 切换的精确增减）
  - `checkInLocation`（签到，确定性 ID 含中国时区日期）
- `comment-create` 新增 `requestId` 幂等键：同一次提交重试只会落一条评论，且评论写入与 `commentCount` 递增同事务。
- **收藏数收敛为单一真源**：`locations.favoriteCount` 由 `toggleFavorite` 在事务中维护；`getLocations` 与 `getLocationDetail` 优先读该字段，仅历史数据缺字段时才回退精确计数。
- `addLocation` / `post-create` 补齐计数器初始值（`favoriteCount` / `checkinCount` / `reactionUpCount` / `reactionDownCount` / `commentCount`），避免 `undefined` 参与运算。
- 所有事务型云函数使用 `cloud.database({ throwOnNotFound: false })`，避免「记录不存在」抛异常导致整个事务回滚。
- 并发写入命中同一 ID 时按幂等成功处理（`isDuplicateKeyError`），不再向用户报错。

## P0-02｜审核策略统一为 fail-closed

**根因**

各云函数的 `contentSecurity.js` 在审核接口异常时返回 `pass: true`（直接放行），而公开读接口只过滤 `hidden`、**不排除审核未通过状态** → 审核服务抖动期间未过审内容对外可见。

**修复**

- `cloudfunctions/shared/contentSecurity.js` 统一为 fail-closed，并引入明确状态机：
  - 通过 → `pass: true, moderationStatus: 'approved'`
  - 违规 → `pass: false, moderationStatus: 'rejected'`
  - **审核服务不可用 → `pass: false, moderationStatus: 'pending'`**（拒绝发布并提示稍后重试，而不是放行）
- 新增 `describeFailure()`：把「审核服务不可用」与「内容违规」区分开，不再用「图片包含违规内容」误导用户（图片超 1 MiB 现在提示「体积过大，请压缩」）。
- 同步到 `addLocation` / `post-create` / `updateContent` / `comment-create`；发布与编辑成功后显式写入 `moderationStatus: 'approved'`。
- **9 个公开读接口统一过滤**非 approved 内容（仅作者本人可见）：
  `getPosts`、`getLocations`、`getLocationDetail`、`post-detail`、`searchLocations`、`getTagContent`、`getSeasonalLocations`、`getLeaderboard`、`getUserPublicContent`

> 注：为兼容历史数据，无 `moderationStatus` 字段的旧记录仍按公开处理。

## P0-07｜互动缺少提交锁

**根因**

点赞、收藏、反应、评论、签到均无 in-flight 锁；收藏甚至「先弹成功提示再发请求」，失败只静默回滚。

**修复**

- `post-detail`：点赞 / 收藏 / 反应 / 评论提交 / 评论点赞各自加锁（评论点赞按评论 ID 分别加锁）；评论发送中按钮显示「发送中…」并禁用。
- `location-detail`：收藏 / 反应 / 签到 / 加入合集加锁；**收藏成功提示移到服务端确认之后**；补上收藏前的登录校验（此前发现页卡片有、详情页没有）。
- **服务端权威回写**：不再用 `setData(res.data)` 整体覆盖页面状态，只回写本操作涉及的字段；计数按「服务端最终状态 − 操作前状态」的差值校正，重复请求不会造成偏移。
- `addToCollection` 的 ActionSheet 回调补上 `try/catch`（此前断网会静默失败），并区分「已加入合集」与「该地点已在合集中」。

## P0-05｜错误响应被渲染为帖子

**根因**

`post-detail` 页面在 `res.data` 缺失时把**整个错误包**当作 post 渲染，且不校验 `code` → 已删除/下架/无权限的动态显示为空白详情。

**修复**

- 只接受 `code === 0 && data` 的响应；否则展示独立错误态（标题 + 原因 + 「重新加载」/「返回」）。
- 评论加载失败同样不再伪装成「暂无评论」，改为独立错误态 + 「重新加载评论」。
- 顺带支持 `scene` 解析，无有效 ID 时直接给出「动态链接已失效」。

## P0-06｜comment-list 权限绕过

**根因**

`comment-list` 不校验目标内容可见性，也未过滤审核隐藏的评论 → 只要知道 ID，就能读到圈内内容或已下架内容的评论。

**修复**

- 读取评论前先校验目标（帖子/地点）存在性、`hidden` 状态、`circle` 可见性与 `moderationStatus`，与 `post-detail` 的权限判断保持一致。
- 顶层评论与回复均增加 `moderationStatus: _.neq('hidden')` 过滤。
- 限制 `targetType` 仅允许 `post` / `location`。

## P0-08｜搜索竞态导致骨架屏永久转圈

**根因**

输入联想与正式搜索**共用同一个 `_requestVersion`**：输入触发的联想请求会让正在进行的正式搜索被判定为「过期」并 `return`，而 `isSearching` 又不复位 → 骨架屏永久转圈。

**修复**

- 拆分为 `_suggestVersion` 与 `_searchVersion` 两个独立版本号。
- 确认搜索时清除未触发的联想定时器并使联想版本失效。
- 业务失败不再伪装成「没有找到相关内容」，新增独立失败态 + 「重试」。
- `loadMore` 同样补齐 `code` 校验与错误态。
